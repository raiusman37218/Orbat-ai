## 3. Decisions Log

1. **Preserving `conversations.status` while adding `conversations.handoff_status`**:
   - `conversations.status` has an existing `CHECK (status IN ('open', 'closed', 'snoozed', 'pending'))` constraint and a bidirectional sync trigger with `tickets.status`.
   - Stored the 6 handoff states (`bot_active`, `handoff_offered`, `waiting_for_agent`, `agent_active`, `offline_queued`, `resolved`) in `conversations.handoff_status` and synchronized `handoff_status = 'resolved'` ↔ `status = 'closed'` via a DB trigger.
2. **Reusing `public.agent_notification_preferences`**:
   - Following Golden Rule 3 ("Reuse, never duplicate"), extended `public.agent_notification_preferences` with `ADD COLUMN IF NOT EXISTS` for sound, Web push, email, and Telegram settings.
3. **Reusing `workspaces.business_hours`, `workspaces.timezone`, and `public.workspace_holidays`**:
   - Supported both `{ open, close, enabled }` and `{ start, end, active }` day formats so existing schedules continue working seamlessly.
4. **Preventing Premature Auto-Assignment on New Conversations**:
   - Updated `fn_auto_assign_conversation_on_create()` so that when a conversation starts in `handoff_status = 'bot_active'` (AI answers first), `assigned_agent_id` remains `NULL` until an agent explicitly claims the conversation via `claim_conversation()`.
5. **Email Sending Architecture**:
   - Created `/api/notifications/handoff-email` route using existing SMTP (`loadTeamAlertSmtp` / Platform SMTP / Postmark fallback) for missed chats, unanswered alerts, queue summaries, and offline customer replies.
6. **Backward Compatibility with Existing Test Suite**:
   - Preserved `parseHandoverNote` and `generateHelpDeskResponseWithHandover` return types, ensuring all existing tests pass while adding new handoff triggers and state machine checks.
7. **Widget Bundle Isolation**:
   - Compiled `widget/src/index.ts` to `public/widget.js` using esbuild without increasing Next.js bundle size.
8. **Dual-Layer AI Silencing**:
   - Checked `canAiRespond` in Next.js API route before generation AND enforced state constraints in Postgres `fn_deliver_ai_reply` RPC to guarantee AI never interrupts human agents.
9. **Realtime Ringing and Web Audio Chimes**:
   - Synthesized natural acoustic chime via Web Audio API oscillators, eliminating missing asset 404s and enabling audio across all browsers.
10. **Pinned Handoff Summary Card in ChatThread**:
    - Replaced basic banner with a structured card displaying reason pill, AI summary bullets, requested timestamp, live wait duration, and claim / return-to-AI action buttons.
11. **Channel Fallback Integration**:
