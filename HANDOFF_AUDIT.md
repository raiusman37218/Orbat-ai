## 3. Decisions Log

1. **Preserving `conversations.status` while adding `conversations.handoff_status`**:
   - `conversations.status` has an existing `CHECK (status IN ('open', 'closed', 'snoozed', 'pending'))` constraint and a bidirectional sync trigger (`trg_sync_conversation_ticket`) with `tickets.status`, plus 50+ references in Next.js API routes, server actions, and dashboard filters.
   - Changing `conversations.status` values would break existing working behavior (violating Golden Rules 2, 5, and 7).
   - Therefore, we store the 6 handoff states (`bot_active`, `handoff_offered`, `waiting_for_agent`, `agent_active`, `offline_queued`, `resolved`) in `conversations.handoff_status` and synchronize `handoff_status = 'resolved'` ↔ `status = 'closed'` via a `BEFORE INSERT OR UPDATE` trigger on `conversations`.
2. **Reusing `public.agent_notification_preferences` instead of creating a duplicate table**:
   - Following Golden Rule 3 ("Reuse, never duplicate"), since `public.agent_notification_preferences` already exists (`20261013090000_settings_hub.sql`), we extend it with `ADD COLUMN IF NOT EXISTS` for `sound_enabled`, `sound_name`, `push_enabled`, `email_missed`, `email_queue_summary`, `telegram_chat_id`, and `telegram_enabled`, while keeping its existing `email jsonb` column intact.
3. **Reusing `workspaces.business_hours`, `workspaces.timezone`, and `public.workspace_holidays`**:
   - `workspaces` already has `business_hours jsonb` (with `enabled`, `timezone`, and per-day `mon`..`sun` `{ enabled, open, close }` / `{ active, start, end }`) and `timezone text`, and `public.workspace_holidays` (`workspace_id`, `holiday_date`, `name`, `recurring`) is already used by SLA calculations (`fn_sla_timezone`, `fn_sla_is_holiday`).
   - Our `fn_is_within_office_hours(p_workspace_id)` and `fn_next_office_hours_open(p_workspace_id)` functions read `workspaces.business_hours`, `workspaces.timezone`, and `public.workspace_holidays`, supporting both `{ open, close, enabled }` and `{ start, end, active }` day formats so existing saved schedules work without migration friction.
4. **Preventing Premature Auto-Assignment on New Conversations**:
   - `fn_auto_assign_conversation_on_create()` previously assigned every new conversation on `INSERT` to an online agent. We updated it so that when a conversation starts in `handoff_status = 'bot_active'` (AI answers first), `assigned_agent_id` and `agent_id` remain `NULL` until an agent explicitly claims the conversation via `claim_conversation()`.
5. **Email Sending Architecture for `send-alert-email`**:
   - Zentry already uses Nodemailer SMTP (`src/lib/email/smtp.ts` + `src/lib/email/workspace-smtp.ts` with Workspace SMTP → Platform SMTP fallback) and Postmark (`src/lib/channels/email/providers/postmark.ts`).
   - Because Supabase Edge Functions run on Deno where raw TCP port 465/587 SMTP can be restricted or when SMTP secrets live in `workspace_secrets`, the `send-alert-email` Edge Function delegates to the Next.js internal endpoint `POST /api/notifications/handoff-email` (authenticated with `CRON_SECRET` / `SUPABASE_SERVICE_ROLE_KEY`), which uses `loadTeamAlertSmtp(workspaceId)` (Workspace SMTP → Platform SMTP) and Postmark fallback, and can also be called directly from server routes and `requeue_stale()`.
6. **Backward Compatibility with Existing Vitest Suite (87 files, 1,336 tests)**:
   - Existing unit tests (`bot-pipeline.test.ts`, `intent.test.ts`, `handovers.test.ts`, `support-agent.test.ts`, `auto-respond/route.test.ts`) test `generateHelpDeskResponseWithHandover` and `parseHandoverNote`.
   - We keep `parseHandoverNote` and `generateHelpDeskResponseWithHandover`'s existing return fields intact while adding `structuredHandoff` (`{ answer, confidence, needs_human, reason }`), offer-vs-confirm state transitions, and cooldown handling.
